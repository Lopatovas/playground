# Database and data model

## Current prototype persistence

The current PR keeps scan reports in memory inside `ScansService`:

```ts
private readonly reports = new Map<string, ScanReport>();
private readonly scanOrder: string[] = [];
```

This is enough for local prototype behavior and tests, but it means:

- reports disappear when the API restarts
- scan history is process-local
- recurring comparison only works within the same runtime session
- multi-user/tenant isolation is not persisted

Production should move these structures into PostgreSQL and object storage.

## Conceptual model

```text
Tenant
  -> User
  -> Dataset
    -> DatasetFile
    -> Scan
      -> TableProfile
        -> ColumnProfile
      -> Finding
      -> ScoreBreakdown
      -> Report
      -> ScanComparison
  -> AuditEvent
```

## Entity overview

### tenants

Represents one customer/account.

Important fields:

- `id`
- `name`
- `region`
- `retention_policy`
- `created_at`

### users

Users belonging to a tenant.

Important fields:

- `id`
- `tenant_id`
- `email`
- `role`
- `created_at`

Suggested roles:

- `admin`
- `analyst`
- `viewer`
- `compliance`

### datasets

Logical grouping for scans. The same dataset name is used for recurring comparison.

Important fields:

- `id`
- `tenant_id`
- `name`
- `description`
- `source_type` such as `csv`, `xlsx`, `database`, `warehouse`
- `created_by`
- `created_at`

### dataset_files

Uploaded files or future references to source tables.

Important fields:

- `id`
- `dataset_id`
- `scan_id`
- `original_name`
- `content_type`
- `size_bytes`
- `storage_key`
- `sha256`
- `retention_expires_at`
- `created_at`

Security note: raw files should live in encrypted object storage, not in PostgreSQL.

### scans

One readiness scan execution.

Important fields:

- `id`
- `tenant_id`
- `dataset_id`
- `status`: `queued`, `processing`, `completed`, `failed`
- `audience`
- `overall_score`
- `previous_scan_id`
- `error_message`
- `created_at`
- `completed_at`

### table_profiles

Profile of a parsed file/sheet/table.

Important fields:

- `id`
- `scan_id`
- `name`
- `row_count`
- `column_count`
- `duplicate_rows`
- `duplicate_rows_percent`

### column_profiles

Profile of one column inside a table profile.

Important fields:

- `id`
- `table_profile_id`
- `name`
- `inferred_type`
- `total_rows`
- `missing_count`
- `missing_percent`
- `unique_count`
- `unique_percent`
- `pii_types` as `text[]` or `jsonb`
- `sample_patterns` as `text[]` or `jsonb`

### findings

Traceable issue generated by deterministic rules.

Important fields:

- `id`
- `scan_id`
- `table_profile_id`
- `column_profile_id`
- `category`
- `severity`
- `title`
- `description`
- `affected_rows_percent`
- `evidence`
- `score_impact`
- `recommendation`
- `rule_id`
- `created_at`

### score_breakdowns

Category-level scores for each scan.

Important fields:

- `id`
- `scan_id`
- `category`
- `label`
- `score`
- `weight`
- `rationale`

### reports

Rendered report payloads. Store JSON for flexibility while report formats are evolving.

Important fields:

- `id`
- `scan_id`
- `format`: `json`, `html`, `pdf`
- `content` as `jsonb`
- `storage_key` for exported HTML/PDF files
- `created_at`

### audit_events

Security and operational audit trail.

Important fields:

- `id`
- `tenant_id`
- `user_id`
- `event_type`
- `resource_type`
- `resource_id`
- `metadata` as `jsonb`
- `created_at`

Examples:

- `dataset.uploaded`
- `scan.started`
- `scan.completed`
- `report.viewed`
- `file.deleted`
- `llm.enhancement.requested`

## Suggested PostgreSQL schema

```sql
create table tenants (
  id uuid primary key,
  name text not null,
  region text,
  retention_policy jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now()
);

create table users (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  email text not null,
  role text not null,
  created_at timestamptz not null default now(),
  unique (tenant_id, email)
);

create table datasets (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  name text not null,
  description text,
  source_type text not null,
  created_by uuid references users(id),
  created_at timestamptz not null default now(),
  unique (tenant_id, name)
);

create table scans (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  dataset_id uuid not null references datasets(id),
  status text not null,
  audience text not null default 'mixed',
  overall_score integer,
  previous_scan_id uuid references scans(id),
  error_message text,
  created_at timestamptz not null default now(),
  completed_at timestamptz
);

create table dataset_files (
  id uuid primary key,
  dataset_id uuid not null references datasets(id),
  scan_id uuid not null references scans(id),
  original_name text not null,
  content_type text not null,
  size_bytes bigint not null,
  storage_key text,
  sha256 text,
  retention_expires_at timestamptz,
  created_at timestamptz not null default now()
);

create table table_profiles (
  id uuid primary key,
  scan_id uuid not null references scans(id),
  name text not null,
  row_count integer not null,
  column_count integer not null,
  duplicate_rows integer not null,
  duplicate_rows_percent numeric(6,2) not null
);

create table column_profiles (
  id uuid primary key,
  table_profile_id uuid not null references table_profiles(id),
  name text not null,
  inferred_type text not null,
  total_rows integer not null,
  missing_count integer not null,
  missing_percent numeric(6,2) not null,
  unique_count integer not null,
  unique_percent numeric(6,2) not null,
  pii_types jsonb not null default '[]'::jsonb,
  sample_patterns jsonb not null default '[]'::jsonb
);

create table findings (
  id uuid primary key,
  scan_id uuid not null references scans(id),
  table_profile_id uuid references table_profiles(id),
  column_profile_id uuid references column_profiles(id),
  category text not null,
  severity text not null,
  title text not null,
  description text not null,
  affected_rows_percent numeric(6,2),
  evidence text not null,
  score_impact integer not null,
  recommendation text not null,
  rule_id text not null,
  created_at timestamptz not null default now()
);

create table score_breakdowns (
  id uuid primary key,
  scan_id uuid not null references scans(id),
  category text not null,
  label text not null,
  score integer not null,
  weight numeric(5,4) not null,
  rationale text not null
);

create table reports (
  id uuid primary key,
  scan_id uuid not null references scans(id),
  format text not null,
  content jsonb,
  storage_key text,
  created_at timestamptz not null default now()
);

create table audit_events (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  user_id uuid references users(id),
  event_type text not null,
  resource_type text not null,
  resource_id uuid,
  metadata jsonb not null default '{}'::jsonb,
  created_at timestamptz not null default now()
);
```

## Recommended indexes

```sql
create index scans_dataset_created_at_idx on scans(dataset_id, created_at desc);
create index scans_tenant_status_idx on scans(tenant_id, status);
create index findings_scan_severity_idx on findings(scan_id, severity);
create index findings_rule_id_idx on findings(rule_id);
create index table_profiles_scan_idx on table_profiles(scan_id);
create index column_profiles_table_idx on column_profiles(table_profile_id);
create index audit_events_tenant_created_at_idx on audit_events(tenant_id, created_at desc);
```

## Retention model

Default recommendation:

- Raw uploads: delete after report generation unless tenant config says otherwise.
- File hash and metadata: retain for deduplication and audit.
- Profiles/findings/scores/reports: retain for recurring comparison.
- Audit events: retain according to customer contract and compliance requirements.

## Migration path from current prototype

1. Add Postgres and an ORM/query layer.
2. Replace `ScansService.reports` and `scanOrder` with repositories.
3. Store raw uploads in encrypted object storage.
4. Persist profiles, findings, score breakdowns and reports after each scan.
5. Resolve `previous_scan_id` by latest completed scan for the same `tenant_id + dataset_id`.
6. Add background jobs for medium/large files.
